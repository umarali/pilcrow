# Core

This is the exact contract for `PilcrowCore`. Its tests and this document
change together when the contract changes.

`PilcrowCore` owns identity, timing, geometry, transcript alignment, export names and per-mark fix lists. It imports Foundation only. The App owns capture, audio, image rendering, files and delivery. Core, MCP and their tests compile in Swift 6 language mode; the App still builds in Swift 5 mode ([#11](https://github.com/umarali/pilcrow/issues/11)).

Times are seconds on one monotonic session clock whose origin `t0` is when the session opens. The App uses the same uptime time base as `NSEvent.timestamp` and `ProcessInfo.systemUptime`.

## Model and capture lifecycle

`MarkID` is an integer. A session issues `1` first and reserves finished visible numbers even after deletion. A number allocated at pen-down can be reused if that gesture becomes an absorbed head at pen-up. `Frame` and `Stroke` conform to `Identifiable`. Frame references use `Frame.ID`, an alias for `UUID`; stroke IDs use `MarkID`.

`NormalizedPoint` has a top-left origin, x rightward and y downward. Its coordinates are fractions of the frame, normally `0...1`; storage does not clamp them. `Point` and `Size` express raw coordinates and dimensions in the units named by their caller.

A `Frame` registers one capture's identity and coordinate space:

- `id`, `displayID: UInt32` and `boundsInPoints: Size` identify its display and size in AppKit points. The App retains the screen origin separately.
- `context: FrameContext?` optionally stores `appName`, `windowTitle` and `bundleID` from the window under the first mark. Missing context decodes as nil and does not affect geometry or capture validation.
- `boundsInPoints` must have finite positive width and height, including while pending.
- `capturedAt: Double?` and `pixelSize: Size?` are both nil while pending. `captureFailed` starts false. A complete frame has a finite capture time and finite positive pixel dimensions, with `captureFailed == false`. `isComplete` checks those capture fields. Session validation requires integer pixel dimensions and also requires the pixel aspect divided by the point aspect to be within `0.99...1.01`, inclusive. The logarithmic comparison allows `1e-12` rounding tolerance at the boundaries.
- Core metadata does not prove an image file was written; the App must report completion only after capture succeeds.

Register before pen-down, then complete after asynchronous capture succeeds:

```swift
var session = Session() // Non-throwing empty initializer.
let frame = Frame(id: Frame.ID(), displayID: 1,
                  boundsInPoints: Size(width: 800, height: 600))
try session.addFrame(frame)
let mark = try session.beginStroke(at: 1, frame: frame.id,
                                   firstPoint: NormalizedPoint(x: 0.4, y: 0.5))
// Drawing can continue while capture is pending.
try session.completeFrame(id: frame.id,
                          pixelSize: Size(width: 1600, height: 1200), capturedAt: 1.1)
```

`updateFrame(_:)` can replace metadata using the same ID. It cannot change the display or point bounds because stored normalized strokes refer to that coordinate space. A complete frame cannot become pending or failed. Complete-to-complete metadata replacement remains allowed if the geometry validates. A complete `Frame(id:capturedAt:displayID:boundsInPoints:pixelSize:)` may also be registered directly.

Call `failFrame(id:)` when capture reports an actual failure. It sets `captureFailed` without removing the pending frame or its strokes. Repeated failure is harmless. Pending frames appear in `OutgoingMessage.pendingImages` and failed frames in `failedImages`; fix items distinguish `pendingFrame` from `failedFrame`. Before sealing, a failed frame can complete on retry, which clears `captureFailed`, or explicitly return to pending through `updateFrame` with nil capture fields and `captureFailed == false`. Neither changes mark IDs or timing. Unknown frame IDs are rejected; strokes cannot reference an unregistered capture.

Frame Codable accepts older complete-frame JSON with numeric `capturedAt` and `pixelSize`, and pending metadata omitted or null. Missing `captureFailed` defaults to false. Session decoding validates point bounds, capture metadata, aspect ratio and frame references. Unsealed pending and failed sessions round-trip and can complete after reload.

`Stroke` stores `id`, `frameID`, `downTime`, optional `upTime`, normalized `points`, `badgeAnchor`, `isDeleted` and optional `shape`. The first point becomes the freehand badge anchor. An open stroke has nil `upTime` and `shape` and remains live. Older strokes decode without `shape` and keep their freehand rendering and fix-list text. Arrow shafts can store a rendered point count and a reversed direction. Absorbed head strokes use negative IDs and reference the visible shaft. A head that changes the shaft also stores its earlier shape and direction for undo.

`TranscriptWord` stores `text`, `start`, `end`, `isFinal` and `isEstimated`. Word timings are estimates, including SpeechTranscriber per-run timing distributed into words. `isEstimated` defaults to true in the initializer and when decoding older JSON without the key. Producers may explicitly set false when they have measured word timings.

## Session operations and errors

`Session()` is non-throwing. The initializer accepting stored state validates it and throws. `strokes`, `frames` and `nextMarkNumber` are read-only externally. Before sealing, callers can replace `words` or use `setTranscript(words:languageCode:)` to update the words and their transcriber language together. Older session JSON defaults to an unknown language.

`Session.ValidationError` has these cases:

- `duplicateStrokeID`: stored strokes repeat a mark ID.
- `duplicateFrameID`: stored frames repeat an ID, or `addFrame` repeats one.
- `unknownFrameID`: stored strokes, `beginStroke`, `updateFrame`, `completeFrame` or `failFrame` reference an unregistered ID.
- `exhaustedMarkIDs`: stored ID `Int.max` prevents advancing the counter, or `beginStroke` cannot issue a new ID.
- `nonFiniteTime`: `beginStroke` receives NaN or either infinity.
- `nonFinitePoint`: either coordinate passed to `beginStroke` is NaN or infinite.
- `invalidFrameBounds`: registered or decoded point bounds are non-finite or non-positive.
- `invalidFrameCapture`: only one capture metadata field is supplied, or capture time/dimensions are invalid, including fractional pixel dimensions.
- `frameGeometryMismatch`: `updateFrame` changes the registered display or point bounds, or any complete frame has more than 1% relative aspect mismatch.
- `sealedSession`: any throwing mutation is attempted after sealing. This is checked before other errors.
- `invalidFrameTransition`: a complete frame becomes incomplete, or a failed frame supplies capture metadata.

Mutating operations validate before writing. `addFrame`, `updateFrame`, `completeFrame` and `failFrame` throw. `beginStroke(at:frame:firstPoint:)` throws with the reason instead of returning nil, and its result must be used or explicitly ignored. Before sealing, it checks non-finite time, unknown frame, exhausted IDs and non-finite first point in that order. These errors leave the session unchanged.

`append(point:to:)` ignores non-finite points and missing, ended or deleted strokes; each is a documented no-op. Finite out-of-frame coordinates remain valid and are not clamped. Stored strokes supplied to the state initializer retain their coordinates, so malformed legacy geometry can still produce an `invalidGeometry` crop reason. `endStroke(id:at:)` ignores missing, deleted or ended strokes, non-finite times, and times before pen-down. `deleteMark(id:)` hides a mark and reserves its ID. `undoLatestMark(in:)` undoes the latest gesture in the provided frame IDs, including an absorbed head.

`seal()` is non-throwing and idempotent. It converts every still-pending capture to failed, retains complete captures, and sets read-only `isSealed`. All frame mutations and `beginStroke` then throw `sealedSession`; `append`, `endStroke`, `deleteMark`, `undoLatestMark` and writes to `words` become no-ops. This also blocks late speech recognition. Sealing does not invent pen-up times for open strokes. A sealed session round-trips through Codable and remains sealed; older JSON defaults to open. Decoding sealed JSON with pending frames finalizes them as failures. Retries are allowed only before sealing.

`liveMarks` contains visible strokes in stored session order, also called mark order. Deleted marks and absorbed heads are excluded. `framesWithMarks` contains only frames with live marks, ordered by each frame's first stored stroke, including deleted strokes on frames that still have another live mark. This is drawing order rather than capture-array or timestamp order. A frame whose every mark is deleted is omitted.

The allocation counter is the maximum of 1, the supplied or decoded counter, and one past the highest stored ID, including deleted marks. Pen-up absorption releases the provisional number. If Core receives overlapping strokes, it also stores any numbers released out of order so they can be reused after decoding. Older JSON without a counter is accepted. Validation failures surface as `ValidationError`; malformed JSON may produce standard decoding errors.

### Shape recognition (D-25 and D-28)

`Session.endStroke(id:at:)` classifies ink in top-left frame points, even while capture is pending. Raw samples and the original badge anchor stay in the session.

- A bounding diagonal of at most 6 pt makes a pin.
- An area spans at least 3 pt per axis, travels at least 16 pt, encloses at least 8 pt² and closes within 28% of its bounds' diagonal. A seam between opposite-facing corners cannot stand in for a missing side. The classifier searches both ends of the ink for a closer seam. It can trim up to 40% of the travelled distance when the two sides of that seam meet within 4 pt or 4.5% of the original diagonal, whichever is larger. Area uses the tighter of the frame-aligned and oriented bounds, filling at least 30% of that box or 55% when it is at least four times as long as it is wide.
- Tidying needs a 12 pt span on both axes and one circuit around the center. The loop's angular travel and the original ink's net angular travel each cap at 1.4 turns. An area keeps its ink if a trimmed tail strays farther than `max(14, 0.3 × short side)` pt from the loop. The recognizer can also keep a loop with a tail that takes up more than 40% of the travel. For tidying, the loop must fill at least 80% of its convex hull. Four or five distinct corners with straight runs make a box. Each box edge allows a bow of 4.5% of its chord, bounded between 16% and 40% of the short side. For softer contours, the recognizer compares the mean oval and box errors. An oval error above 0.75 times the box error favors a box if the box error is at most 0.08 of the short half-axis. The rest keep their ink unless the oval fit passes. Tidy rectangles and ellipses use the retained loop's frame-aligned bounds.
- An arrow shaft travels at least 30 pt and at most 1.2 times its start-to-tip chord, with turns under 60° over a local 10 pt window on each side. It can start or end inside or within 20 pt of a completed, live pin or area on the same frame. A pin's badge also counts. The closest outline hit wins, then the smaller footprint, then the most recent mark. Outside hits must gain clearance locally and by at least half the chord overall. This keeps parallel underlines plain. An arrow with a drawn head or source link can look ahead from a tip without a nearby hit for up to `min(90, 0.3 × chord)` pt. An arrow with a drawn head or a target link can look back from a start without a nearby hit for up to `min(40, 0.15 × chord)` pt. Both rays follow the local direction of the shaft over up to 30 pt. A later pin or area can fill a free link on an earlier arrow in the same frame. A shaft with both ends in one mark stays plain unless it has a drawn head, in which case it is an unlinked arrow.
- A same-stroke head reverses by at least 115°. The farthest sample must be at least 12 pt from the tip and no farther than the smallest of 90 pt, 35% of travelled distance and 55% of shaft chord. Measuring the farthest sample lets the stroke return to the tip and draw a second barb. Pilcrow draws the clean head using the shaft prefix. A follow-up V can supply a head at either end if its bounds fit within 110 pt, its apex sits near the end, its legs are balanced and it opens back along the shaft. Its arm ends must straddle the shaft axis, with 4 pt of slack. Straight legs stay close to their chords with up to 2.5 pt of backtracking. A lone straight barb within 6 pt can supply a head at pen-up. Two consecutive barbs can reach 14 pt from either end when their contacts are within 14 pt of each other and the legs open back on opposite sides of the shaft. The longer leg may be at most 1.7 times the shorter leg. At the shaft's start, a first barb stays visible until a partner completes the head. Each gesture starts within 3 s of the prior pen-up. A head at pen-down reverses the arrow. Absorbed gestures keep their original ink and timings. Their provisional numbers become available again and their hidden IDs stay out of the transcript, fix list and images.
- Arrows store optional `from` and `to` IDs. Older `linkedTo` values decode as `from`. The fix list drops a link to a deleted, missing or different-frame mark. Undo removes all absorbed heads of a shaft together. It restores the shaft's pre-head shape and direction if the heads changed them. If the heads left the shaft looking the same, undo removes the shaft too. A restored shaft accepts a redraw for up to 3 s after the head undo.

`ShapeRecognizer.version` is `"d28-forgiving-v4"`. Bump it when recognition rules change.

`Export.write` best-effort writes local `strokes.json` beside `message.md`, including when images are unavailable. `StrokeRecording` in Core writes schema version 3:

| Field | Meaning |
| --- | --- |
| `version`, `recognizerVersion` | Schema integer `3` and the Core recognition-rules string at export time |
| `strokes` | Live marks and their absorbed strokes in drawing order. Deleted strokes are omitted. |
| `id`, `frameID` | Visible mark or hidden gesture identifier, and frame identifier |
| `frameSize`, `displayScale` | Frame width/height in points; capture pixels per point, or explicit `null` if pixel metadata is unavailable |
| `shape` | Stored live classification; omitted for unclassified legacy/open marks |
| `points` | Top-left frame-point `x`/`y` Double values with full JSON precision, no decimal rounding |
| `originalPointCount`, `decimated` | Input count and whether storage dropped samples |
| `resampleMethod` | `"none"` through 5,000 points; `"uniform-index"` above that, selecting 5,000 original samples evenly by index including both endpoints |
| `downTime`, `upTime` | Session-clock seconds. Open marks omit `upTime`. |
| `absorbedInto` | Shaft ID on a separate head stroke |
| `shaftEnd` | Rendered tip in frame points for a shortened or reversed shaft |
| `shaftReversed` | True when a separate head makes the original pen-down point the arrow tip. Omitted in older recordings. |

This does not alter session ink. The encoded file is capped at 5,000,000 bytes per capture. Encoding, size-limit, write or copy failure only logs a generic `os.Logger` message with no points, paths or transcript; it cannot fail export, recovery or publication and does not enter the visible files-failed count. Recovery/publication validate a user-owned regular source and its size, then use `FileManager.copyItem` without reading the file into a Data buffer. The JSON follows capture retention/discard and stays local. It is never added to the clipboard, agent text, CLI image paths or MCP attachment manifest. MCP ignores extra capture files and rejects `strokes.json` even if a malformed manifest lists it as an image.

Decode with `JSONDecoder().decode(StrokeRecording.self, from: data)`, then call `record.replay(existingMarks:)`. The helper feeds recorded frame points directly into the current `ShapeRecognizer`, avoiding a divide/multiply normalization round trip. For arrows, pass the original earlier same-frame marks as they existed at pen-up; the helper filters by frame and the recognizer ignores deleted/open sources. To replay absorption or links to later marks, feed all records in drawing order through Session. A single record lacks the adjacent gesture and any previously deleted context omitted from export. Exact replay is tested for non-decimated records under the same rules, including fitted bounds and arrow links. Decimated data is explicitly approximate. The decoder also reads schema 2, including its positive IDs for absorbed heads. Schema 1 lacks the fields required for full-precision replay.

`debug/voice.json` is best-effort and stays under the local capture folder's 24-hour outbox retention. It records final transcript words with session-clock audio times, ordered result ranges and final flags, the raw words from final results before overlap filtering, and pen-down and pen-up times. It has a 999,999-byte file limit and flags a truncated result trace. It stays outside the attachment manifest and agent messages.

## Alignment and transcript rendering

`Aligner.place(words:strokes:onlyFinal:)` drops deleted or absorbed strokes and words with non-finite start or end times. `onlyFinal: true` also drops non-final words before placement. The default includes provisional words. Words sort by start, then end, then original order.

A finite stroke's slot is the count of words whose start is at or before pen-down. A mark at a word's start follows that word. In gaps it follows the last word started; before all words it leads. All overlapping words already started precede the mark. Finite marks in a slot sort by down time, then ID. Non-finite stored pen-down times trail all words and finite marks, in ID order. With no words, finite marks precede non-finite marks. Pen-up time does not affect placement.

`TranscriptRenderer.render(tokens:)` splits each word on Swift `Character.isWhitespace`, then joins nonempty parts and `[n]` tokens with single spaces. CRLF and mixed newline runs collapse once. It does not trim Unicode scalars: whitespace and its combining mark are removed as a whole grapheme, so the accent cannot become attached to the following letter. Punctuation stays inside words. There is no trailing newline.

## Image naming and outgoing messages

`MessageBuilder.filenames(for:)` assigns `frame-1.png` through `frame-N.png` to `framesWithMarks` in first-stroke order, including pending frames. Names are consecutive among currently marked frames, so removing every mark from a frame may renumber the remaining frames. Completing a pending frame does not change names. The public builder accepts no caller-supplied filenames; generated names have no path separators or line breaks and cannot collide.

`MessageBuilder.build(session:destinationHint:onlyFinal:visibleText:)` is the single public outgoing-message builder. Its text contains the transcript with inline `[n]`, a blank line, then one quoted fix-list entry per live mark in stored mark order. When a frame has app/window context, its first fix entry gets one frame header. Optional caller-supplied `visibleText: [MarkID: String]` adds `on "…"` per mark, separately from spoken words. `VisibleText.concise` collapses whitespace and limits OCR to 80 grapheme clusters including an ellipsis. The app name and window title are each capped at 120 grapheme clusters including an ellipsis, then escaped onto one line. Missing context and OCR preserve the prior message format. The fix-list Markdown renderer is internal.

```text
sign out [17] over here

- [17] "sign out over here" → mark-17.png (in frame-1.png)
```

`attachments` contains complete marked frame names in first-stroke order, followed by available crop names in live-mark order. Each frame appears once; each available mark crop appears once. Pending or failed captures have neither frame nor crop attachments. Invalid stored stroke geometry can omit a crop while retaining its complete frame attachment. `pendingImages` and `failedImages` contain the corresponding marked frame IDs, each in first-stroke order. A sealed session has no pending images or pending-capture phrases. The read-only compatibility view `missingImages` concatenates pending then failed IDs; new code should use the separate arrays.

`cropPlans` contains one `CropPlan` per attached crop, in the same crop order. Each plan has `sourceFrameID`, `sourceFrameName`, `sourcePixelRect`, `outputSize` and `cropName`. Its rectangle refers to the **original captured image**, with top-left origin, before whole-frame export downscaling. The App must keep that original image, render its annotations, crop the source rectangle, resize the screenshot part within `outputSize`, append any D-31 caption, and write `cropName`. `framePlans` contains one `FramePlan` per complete marked frame, in attachment order, with `frameID`, `outputName` and integer `outputSize` after `Geometry.fitPixels` with `ImageLimits`, before any App caption is appended. Look up original images by these IDs rather than inverting filenames. Do not crop from an already resized frame attachment.

The App must write files **only from the final build** after edits, deletion and capture outcomes settle. Deleting every mark from a frame can renumber later frame filenames; an earlier plan must not be reused. Core plans files but does not write them. The App must surface export failures separately and attach only files it has successfully produced.

There is no trailing newline. Empty sections omit the blank separator. `destinationHint` stays separate from text. `isEmpty` considers text and attachments only. Older `OutgoingMessage` JSON without outcome arrays, `cropPlans` or `framePlans` defaults them to empty. Legacy `missingImages` decodes into `failedImages`: a saved message cannot promise that its missing capture is still in progress. New encoding also emits the combined legacy key for older readers. A legacy crop plan without `sourceFrameID` decodes with nil identity; newly built plans always have an ID. Rebuild legacy plans from the session before exporting, since their frame identity cannot be recovered safely from a filename alone.

### App caption export (D-31)

App export renders `FixList.build(session:)` items' cleaned `words` and shared `kindLabel` into the PNGs. It never substitutes the raw paragraph. A crop with words gets a white strip; a frame panel gets one row for each mark on that frame with words, in mark order, when the panel fits. Empty words add no panel. Body text is 16 px Helvetica, #1d1d1f, at a 22 px line height; kind labels and truncation notes are grey. The overlay's numbered badge renderer also draws the caption badges, at the screenshot's exported badge height and at least 24 px tall. A one-pixel divider separates screenshot and panel. Captioned output retains an RGB source colour profile where available.

Final dimensions include the caption and must fit the same 1,600 px long edge and 1,560,000 pixel caps. Export tries descending screenshot scales with fixed font and badge sizes, preserving source crop rectangles and aspect ratios. A crop strip has at most eight text lines, including any truncation note. A frame panel takes at most 40% of final height, dividing its line budget among rows. If the panel cannot fit, Pilcrow writes the annotated frame without it and keeps the individual crop captions. Truncated lines end with “…” and “(full words in the message)”. Full text stays in `message.md`, the clipboard message and manifest; `message-for-agent.md` adds only a short caption hint. Wordless images keep the existing export path. HUD/Review thumbnails derive from the final captioned crop.

## Per-mark fix list

`FixList.build(session:onlyFinal:visibleText:)` creates one `FixItem` per live mark in mark order, with the full aligned transcript stored separately. Each item has `mark`, `frameID`, `imageName` from the same filename helper, `cropName` such as `mark-3.png`, `cropRect`, `outputSize`, `unavailableReason`, `words`, optional `shape`, `frameContext` and `visibleText`. Either of the item's arrow links can be nil when its endpoint mark cannot be included. Building a plan does not render or write images.

### Crop rule

1. Use the fitted bounds for a tidied area and the dot position for a pin. For freeform ink, including arrows, find the bounding box of rendered stroke points **and the badge anchor**, in the frame's top-left **AppKit points** by multiplying normalized x/y by `boundsInPoints`. An empty point array uses the anchor alone. Negative and out-of-frame points participate in the box.
2. Pad every side by `max(48 pt, 0.25 × max(box width, box height))`, measured in points. For arrows, increase the padding if needed to fit the badge beside the head or tail, including the size it can reach when export enlarges badges for legibility.
3. Expand to at least **320 × 200 pt**, preserving the box's center. Shift inside the point bounds and clamp each dimension to the frame dimension. A smaller display can produce a smaller source crop.
4. Convert the point rectangle to original captured pixels independently per axis, using `pixelSize.width / boundsInPoints.width` and `pixelSize.height / boundsInPoints.height`. Round the pixel origin down and far edges up, staying within the source image. `cropRect` is this source rectangle, **before downscaling**, with `origin: Point` and `size: Size` in pixels.
5. Apply `Geometry.fitPixels` with `ImageLimits` to obtain `outputSize: PixelSize`, whose width and height are integer pixels. Output may be smaller than the minimum source crop.

For a centered dot on a 1000 × 500 pt display captured at 2000 × 1000 px, the source rectangle is x=680, y=300, width=640, height=400 px. A dot at its top-left shifts to x=0, y=0 with the same size. A point-space box from x=300 to 700 and y=200 to 300 pads by 100 pt and becomes 600 × 300 pt at x=200, y=100, or 1200 × 600 px at x=400, y=200. At 1× scale the same point-space crops have half as many pixels. Slight per-axis scale differences within the 1% aspect tolerance use the actual scales.

Huge finite coordinates can overflow intermediate spans; these request full frame dimensions and remain bounded. Non-finite points or anchors produce nil rectangle and output size with `invalidGeometry`. Pending frames use `pendingFrame`; failed captures use `failedFrame`. A defensive `missingFrame` reason exists, although Session validation rejects unregistered references. No live mark is omitted for missing pixels. Badge **anchor** coverage is guaranteed; the App chooses the badge's rendered footprint and must honor its minimum exported height.

### Words rule (D-27)

The App replaces overlapping volatile results by audio range. An older final covers an incoming word when the word's midpoint falls inside the older final's half-open audio range. This applies to incoming finals and volatile results. An incoming volatile result with no words left after trimming leaves the current tail in place. On an analyzer drain timeout, the App keeps the latest provisional tail when retiring that segment.

The exported paragraph keeps the recognizer's wording, punctuation and repetitions after finality and invalid-time filtering. The paragraph's `[n]` placement and fix-line splitting both allow 75 ms for pen-down just after a word starts. A word that already ended can still precede the marker. In overlapping speech, the marker follows the last word that qualifies, preserving transcript order. Direct calls to `Aligner.place(words:strokes:onlyFinal:)` use the exact starts specified in D-13. Whitespace-separated recognition runs retain their timing when split into words for fix lines.

1. **Segment speech.** A pause of at least 0.6 s, full stop, question mark, exclamation mark, colon or semicolon ends a clause. Closing quotes and brackets can follow the punctuation. Initials, dotted abbreviations and `etc.` can keep their periods inside the clause. If the transcript has clause-ending punctuation anywhere, treat adjacent clauses separated only by a pause shorter than 1.5 s as parts of one sentence when choosing an owner. A pen-down or overlapping stroke in the sentence can claim an earlier unassigned part. When the parts have one owner, ordered repair keeps them together.
2. **Assign by timing.** A clause's first matching pen-down gets the lead-in. Later pen-downs take the words since the previous split. The last mark gets the rest of the clause. Equal pen-down times use stored mark order for the initial split. A pen-down can match for 0.3 s after the clause ends, or for 0.5 s if speech outlasts the previous pen-up. If speech has already started in the next clause, keep the earlier tail with marks drawn while it was spoken. Without a matching pen-down, prefer the closest stroke interval within 2.5 s, using overlap to break distance ties. Open strokes and invalid pen-up times use pen-down for both ends. When the nearest stroke is farther away, continue the most recent assignment if the gap from its last assigned speech is at most 2.5 s. The first pass leaves separate speech ending at least 0.6 s before the first mark in the paragraph.
3. **Resolve undo and quick pins.** An undone stroke's words stay in the paragraph. The next live stroke can inherit them when it starts at or after the undone pen-up. Words already assigned to the undone stroke in a clause that began by pen-up count as continuing narration. Any other word that starts in the gap through the redraw's pen-down blocks inheritance. Consecutive live pins and recognized ellipses can share a clause already assigned to the first of them. Each following mark must be at most 1 s after the previous pen-down, with no word starts between those pen-downs and no separate initial assignment for the following mark.
4. **Repair gaps in mark order.** If a mark with nearby speech is empty, or fragments are out of order, match whole fragments to marks from left to right. An empty mark can take a fragment within 2.5 s of its actual `[down, up]` interval, including a neighboring mark's first or last clause if that neighbor has another fragment. Among matches with equal coverage, prefer initial owners, then closer speech. Keep remaining assignments where they fit between the matched fragments. Repair preserves word boundaries chosen by the timing pass and leaves unfilled marks empty.
5. **Share one instruction around a silent run.** After repair, consecutive live marks of any shape can share a complete punctuated sentence spoken entirely before or after the run. The sentence must be the only fragment assigned to the closest mark, and the other marks must be empty. Allow at most 1 s of silence from one pen-up to the next pen-down and between the run and the sentence. Word indices stay ordered and exclusive except when a group shares a fragment.

For example, say "Make this header smaller," wait 1 s and point. Then say "And this one blue," wait 1 s and point again. The repair gives the first clause to the first mark and the second clause to the second mark even if the initial match favored the first mark for both. If "Make this header" and "a bit smaller." are separated by a 0.8 s thinking pause before drawing the next mark, both parts go with that mark. Draw three boxes in silence and then say "These three should be the same size." Each box gets the full sentence when the timing fits the sharing rule. With `move this over here and delete that`, pen-downs just after `this`, `here` and `that` produce `move this`, `over here` and `and delete that`. If the first pen-down is 50 ms into `over`, the paragraph reads `move this [1] over …`. Actual timestamps and punctuation come from the recognizer.

Fix-line cleanup removes trailing ellipses outside quotes and treats the next word as a sentence start. It removes standalone `um`, `uh`, `erm` and `hmm` for English, while preserving quoted forms and mid-sentence capitalized forms such as `Um Bongo`. Immediate repeats of up to four words can collapse when each gap is under 150 ms. Repeats cannot cross sentence endings or quotes. Numbers, common number words, adjacent unit words and single-character CJK tokens retain their repeated forms. A known grammatical or literal double such as `that that`, `had had` or `plus plus` keeps two copies even if spoken three or more times. Other runs collapse to one. Matching ignores case and surrounding punctuation. The retained copy keeps its original spelling and uses the last copy's trailing comma, if any, so `this, this button` becomes `this button`.

### Markdown rendering

`MessageBuilder.build(...).text` contains the full transcript first, then a blank line and one line per fix item:

```text
sign out [3] over here

- [3] "sign out over here" → mark-3.png (in frame-1.png)
```

Shape labels go directly after the number in the fix list, such as `[1] (box)`, `[2] (oval)`, `[3] (area)` or `[5] (point)`. An ellipse within 1.25:1 is a `(circle)`. Arrow labels are `(arrow starting at [1])`, `(arrow pointing at [2])`, `(arrow from [1] to [2])` or `(arrow)` when no links are available. Plain and legacy marks have no shape label. Marks with no words omit the quoted phrase. Inline transcript markers remain just `[n]`.

Inside quoted words, `TextSanitizer` collapses newline runs and escapes only `"` and `\`. Markdown characters such as `#`, `_` and `!` remain untouched. Transcript words retain the renderer's whitespace rules. At the start of each transcript line, after indentation, it escapes only real block openers: a digit run followed by `.` or `)` and then whitespace or end of line; `-`, `+` or `*` followed by whitespace, or three or more consecutive copies of one of those characters; one to six `#` followed by whitespace or end of line; three or more backticks, tildes or underscores; any `>`; and `<` followed by a letter, `/`, `!` or `?`. The ordered-list delimiter is escaped, for example `1\. item` and `1\) item`. This prevents a transcript fence or HTML block from swallowing the fix list without changing ordinary text such as `3.5` or `-5`. The raw `FixList.transcript` and `TranscriptRenderer` output stay plain text.

Unavailable crops keep their planned names and append human phrases: `(screenshot pending)`, `(screenshot not available)` for failed or missing frames, or `(crop not available: invalid geometry)`. These names do not claim a file exists. Empty lists omit the blank separator; an empty session renders an empty string. There is no trailing newline. The result is deterministic for a given session.

## Geometry and legibility

The App must call `Geometry.normalizedPoint(screenPoint:frameOrigin:frame:)` for pen input, including before capture finishes. Pass the mouse location in **AppKit global screen coordinates**, measured in points with bottom-left origin; pass the selected frame display's **bottom-left global screen origin**, such as `NSScreen.frame.origin`, as `frameOrigin`. Register that display's `NSScreen.frame.size` as `boundsInPoints`. Do not pass overlay-local coordinates, a top-left origin or backing pixels, and do not pre-flip or pre-scale the point. Core computes `x = (screenPoint.x - frameOrigin.x) / width` and `y = 1 - (screenPoint.y - frameOrigin.y) / height`. Negative screen origins work, no pixels are needed, and out-of-frame fractions are preserved. Non-finite inputs, non-positive or non-finite bounds, and non-finite conversion results return nil; the App must skip that sample.

`Geometry.pixelPoint` performs the same conversion then multiplies by original captured pixels. `normalize` divides top-left source pixels by `pixelSize`; `denormalize` multiplies frame fractions by it. All three pixel helpers return nil for pending or failed frames, invalid pixel metadata or non-finite input/results. They never substitute zero dimensions for missing captures.

`ImageLimits.maxLongEdge = 1600`, `maxPixels = 1_560_000` and `minBadgeHeightPixels = 24` implement D-17.5. `Geometry.suggestedMaxLongEdge` and `suggestedMaxPixels` alias the corresponding limits. Both fitting functions require explicit caps.

`fit(size:maxLongEdge:maxPixels:)` preserves aspect ratio without upscaling and returns floating-point dimensions. Non-finite or non-positive dimensions or caps return zero dimensions. Floating-point multiplication can exceed the pixel cap by a few ULPs; callers testing it must allow that tolerance.

`fitPixels(width:height:maxLongEdge:maxPixels:)` floors scaled dimensions, with a one-pixel minimum per axis. It does not upscale except for that minimum: `0.5 × 0.5` returns `1 × 1`. Integer outputs honor both caps, including very thin inputs whose other side must shrink to allow the one-pixel minimum. Values stay within representable `Int` bounds. Non-finite or non-positive inputs and caps below one return nil. Both functions compute area scale as `sqrt(maxPixels) / sqrt(width) / sqrt(height)` to avoid intermediate overflow or underflow for huge finite dimensions.

## App wiring contract

Serialize session mutations on one App-owned executor. Retain original captures keyed by frame ID and retain each display's global bottom-left origin separately. Use one clock: let `t0` be the uptime when the session opens, using the time base shared by `NSEvent.timestamp` and `ProcessInfo.systemUptime`. For each pen event use `event.timestamp - t0`. Recognizer times are relative to the audio stream start, so set each word's `start` and `end` to `recognizerTime + (audioStartUptime - t0)`, where `audioStartUptime` is the host time of the first audio buffer, converted with `AVAudioTime.seconds(forHostTime: firstBufferTime.hostTime)` (taking `systemUptime` inside the tap callback runs about one buffer late and places marks too early). Re-anchor `audioStartUptime` whenever the audio engine restarts, and whenever the App starts a new recognition segment on the same input after a gap or overrun. The App subtracts the input's presentation latency and safety offset from the anchor, and clamps a new segment's anchor to the previous audio segment's end and the end of its last retained word. Set `capturedAt` to the uptime when capture completed minus `t0`.

1. Open a non-throwing `Session()` and record monotonic clock origin `t0` as described above. Replace an overlapping provisional result using the recognizer's result audio range. Word timing estimates can shift between hypotheses. An unchanged result counts as final when the recognizer's finalization time reaches the end of its range. On segment handoff, carry forward finalized words. After a drain timeout, keep the retired segment's latest provisional tail. Publish the retained words and the current provisional tail to `session.words` with their `isFinal` and `isEstimated` flags. Finish waits for analyzer completion and queued results within the drain deadline. Pass `onlyFinal: false` when building the outgoing message so any current provisional tail survives. Update words only before `seal()`.
2. On the first stroke of a capture pass on a display, create a pending `Frame` with that display's point bounds, `try addFrame`, then start capture keyed by its ID. Reuse that ID for subsequent strokes in the same pass on that display. A new pass after an underlying click or scroll needs a new frame. If registration throws, surface the error and do not start capture or a stroke on that ID.
3. At pen-down, call `Geometry.normalizedPoint(screenPoint:frameOrigin:frame:)` with global AppKit points and the display's bottom-left origin. If it returns nil, skip the whole stroke and do not call `beginStroke`. Otherwise call `try beginStroke(at:frame:firstPoint:)` and retain the returned mark ID. On an error, surface it and do not append to a nonexistent stroke.
4. During drag, normalize each sample the same way and call non-throwing `append(point:to:)` for valid samples; skip only a nil sample. At pen-up append the final sample, call non-throwing `endStroke(id:at:)` to classify, and invalidate the canvas so the finished shape appears immediately. Undo calls `undoLatestMark(in:)` for the current pass. It removes the most recent gesture. For an absorbed head it restores the shaft or removes it if undo would otherwise leave the same shape and direction. Clearing deletes the relevant live IDs. Undoing the pass's last mark removes its frame from the build, so later `frame-N` names can renumber; write files only from the final sealed build.
5. On capture success, call `try completeFrame` first with integer source dimensions and the capture completion time. Store the captured pixels under the frame ID only if completion succeeds. If it throws `frameGeometryMismatch` for a pending frame, call `try failFrame(id:)` and surface the validation failure. Ignore a second completion for a frame already complete; the App must not call `completeFrame` again. Failure, timeout, permission refusal or cancellation calls `try failFrame` directly, but only while the frame is not complete; a late timeout or failure for a frame that already completed is ignored, not surfaced. Unknown IDs or invalid transitions are integration errors; surface them. After sealing, discard late results and leave the sealed snapshot untouched. A canceled/timed-out task must not later replace a failed outcome unless an explicit retry is still desired before sealing. Exclude Pilcrow's own overlay windows from captures so their ink is not drawn twice.
6. Finish stops accepting new input, ends any open stroke if a valid pen-up time is available, and awaits bounded capture and recognition outcomes. Resolve timeout/cancel outcomes with `failFrame`, then call non-throwing `seal()`. Outstanding pending frames become failed. Call non-throwing `MessageBuilder.build` on that sealed value.
7. Write whole frames from `framePlans` and crops from `cropPlans`, looking up **ORIGINAL captured images by ID**. Burn in the sealed snapshot's ink first, then its badges, in original coordinates before cropping or resizing. Honor the 24 px minimum exported badge height. Whole-frame and crop plans bound the screenshot part. D-31 captions can make the final image taller, so the App further shrinks screenshot pixels to fit the final image limits, without changing source crop geometry or reducing text size. Never crop a downscaled frame attachment. A nil legacy crop source ID requires rebuilding from the session before export.
8. Attach only files actually written successfully, and note export failures in the copied text. If `OutgoingMessage.isEmpty` is true (no words and no live marks), create no capture and copy nothing. A session with speech but no marks is delivered as transcript only. Finish publishes the capture to the outbox and copies the sealed text with those actual files; Review and MCP serve that same sealed snapshot. Do not rebuild from a still-changing session or replace image bytes after publication. Export, publication and delivery are App responsibilities; Core metadata alone does not establish their success.

`MarkRenderer` draws the same geometry in the live overlay and on the export composite, with a 3 pt stroke in the selected Pilcrow colour. A tidied box tries the bounds' top-left corner first. An ellipse tries the upper-left outline at 225° in frame coordinates. A pin puts a 6 pt filled dot at pen-down with a 20 pt tall badge 6 pt to its right. The badge moves left if it would run past the right edge. The renderer and hit test use the same layout. An arrowhead points along the chord to the tip from the most recent sample at least 14 pt back, or the farthest available sample on a short stroke. An arrow linked at both ends tries beside the middle of the shaft. A target-only arrow tries beside the tail. Arrows with no target try beside the head. These are first choices. In mark order, badges try to avoid other arrowheads and earlier badges, and use the first choice when every candidate is blocked (D-32). Frame and crop exports draw the same geometry and preserve the D-17 badge minimum; captioned exports redraw the annotations at their final export scale.
