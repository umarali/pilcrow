# Milestone 1 human live test

Use macOS 26 or later and a disposable document with distinct landmarks near the top and bottom. Use non-sensitive content on every display. Record the macOS version, chip, display arrangement, backing scales, launch method, and actual result for each check.

Stream Pilcrow's log in a separate Terminal window while testing. Frame outcomes, finish reasons, and export results are at notice level.

~~~bash
log stream --info --predicate 'subsystem == "org.pilcrow.app"'
~~~

## Screen Recording gate

Use a fresh permission history. For a signed bundle, follow the reset steps in [Build and sign Pilcrow](building.md). For a bare SwiftPM executable, macOS may attribute access to the launcher, such as Terminal. Start with a launcher without Screen Recording access and clear Pilcrow's saved request flag with the command below. Use the same launcher and build throughout the check.

~~~bash
defaults delete Pilcrow ScreenRecordingRequested 2>/dev/null
~~~

1. Launch Pilcrow, switch to the editor, and press ⇧⌥⌘J. Expect a normal titled Pilcrow Permissions window to appear in front, with a Screen Recording row showing Off and a Grant… button. The rest of the desktop should accept input normally. Verify that Start annotating in the ¶ menu brings forward the same window. Expect no canvas, pill, or macOS prompt from either start command.
2. Click Grant… and leave access off in the macOS prompt. Check that the row stays Off and its button changes to Open System Settings…. Click it and confirm that it lands in Privacy & Security at the screen recording controls. Record the app or launcher listed there. The ¶ menu should also report Screen Recording as Off. Check that the window offers Quit & Reopen under "Already turned it on?" for a bundled app, or gives manual relaunch instructions for a bare executable.
3. Grant access with the Pilcrow window open. The window samples preflight about once a second. Record which outcome macOS gives you. Available follows a successful capture check. "macOS needs Pilcrow to reopen" follows a failed or timed-out check. If the row stays Off, use "Already turned it on?" and Quit & Reopen, or the manual relaunch instructions. If preflight turns true, expect one "Screen Recording probe started" log entry. Leave the window open for several seconds and open the ¶ menu a few times. Expect no further probes until you explicitly start or preflight becomes false and then true again.
4. For either reopen outcome on a bundle, click Quit & Reopen and confirm that a new instance opens and the old one exits. Wait about three seconds (the hotkey retry window), then press ⇧⌥⌘J once in the new instance: expect the overlay if access is now Available, or the permissions window if it is still Off. Finish with Esc before the next step. For a bare executable, quit and relaunch from the same launcher. Start again. The ¶ menu should report Available after the check succeeds. Record which reopen outcomes occurred. If a disposable debug build can force the replacement launch to fail, verify that the old instance shows the failure and recovers ⇧⌥⌘J.
5. Once access is Available, click Start annotating in the window or start again with the hotkey or ¶ menu. Expect one fresh probe per Start. A failed Start that brings up the permissions window shares its probe with the window. On success, the window should close and the overlay should appear. Expect no permission probes while the overlay is open, including when you open the ¶ menu. If macOS asks you to keep allowing screen recording, record when the prompt appears. Release ⇧ to reach the prompt or finish using one of the escape routes below.

## Drawing and passes

1. Put the caret in the test editor, then start with the hotkey. The pill should show 0 marks, Hold ⇧ to draw · Esc finish · ⌘Z undo mark, and the Undo, Clear pass, and Finish buttons. Click and type in the editor with ⇧ released. The editor should receive input, and the ¶ menu should still be clickable. Hold ⇧ alone and draw one stroke. The crosshair check is optional. macOS may keep the cursor from the active app. Release ⇧ partway through the drag, keep moving, then lift the mouse button. The stroke should continue to mouse-up. Click and type again to confirm the editor kept keyboard focus. Check that adding ⌘, ⌥, or Control to ⇧ before clicking leaves the canvas click-through. Pilcrow samples ⇧ about 60 times a second. For repeatable checks, wait a moment after pressing or releasing ⇧ before clicking.
2. In a fresh session, draw two strokes on different landmarks without clicking or scrolling through the canvas between them. Expect badges 1 and 2. Press ⌘Z and check that it removes the second mark and leaves the editor's undo history alone. Draw again and expect badge 3. Finish with Esc and reveal the export from the ¶ menu. Expect one PNG with marks 1 and 3 aligned to the landmarks. Check that the export omits the pill and canvas tint. With the session closed, confirm that ⌘Z reaches the editor again.
3. Draw a mark, release ⇧, and type in the editor without clicking or scrolling. Draw again and confirm that both marks stay visible on the same pass. Release ⇧, scroll the document, then hold ⇧ and draw another mark. The new stroke should start a fresh pass and the earlier marks should disappear from the live canvas. Release ⇧, click something that changes the editor visibly, then hold ⇧ and draw a fourth mark. Finish. Expect three PNGs in order, each with the screen state and marks for that pass.
4. In a fresh session, draw twice, click beneath the canvas, and draw a third stroke. Undo that stroke with the pill while the editor is still active. Expect Undo and Clear pass to disable and the session count to show two. Draw a fourth stroke, click Clear pass, and finish. Only the marks from the first pass should export. The pill should accept the first click even with another app active.
5. Try each finish control with a marked session. Confirm the panels disappear, successful frames export, and the log identifies the control with "Session finished via Esc", "Session finished via hotkey", "Session finished via pill Finish", or "Session finished via ¶ menu". Repeat Esc immediately after start and during a drag. Verify the corresponding Start logs ("Start requested via hotkey", "Start requested via ¶ menu", and "Start requested via permissions window Start") when you try those paths. The display change finish reason is checked below. If an external shortcut utility can reserve Esc or ⌘Z before a session, confirm a rejected registration is named in the pill and the corresponding button still works.
6. Put the editor in a native full-screen Space. Start via hotkey with the pointer in that Space. Verify overlay visibility, drawing, click-through, and keyboard focus without a jump to the desktop. Repeat in Stage Manager if available.
7. Interrupt a drag with Mission Control or a screen lock and release the mouse button and ⇧ while the canvas is out of focus. On return, click the editor and its menu bar with ⇧ released. Both should work and a new ⇧ drag should draw. The log line "Stroke ended after mouse release without mouse-up" means the poll ended the stroke. It can also appear on an ordinary stroke when the poll runs just before the normal mouse-up (known, harmless), so judge this step by the behaviour (editor and menu bar usable, new ⇧ drag draws), not by the log line alone. If the window received mouse-up normally or the session finished on a display change, record lost mouse-up recovery as untested.

## Displays and export

1. With a 1× display to the left of or above a 2× display, start with the pointer on the secondary display. Expect the pill at the bottom right of that display. In one pass, mark asymmetric landmarks on both displays. Expect one PNG per marked display, ordered by the first stroke on each. Check upright badges, stroke alignment near all edges, and no offset from the displays' arrangement. Inspect each PNG at actual size. Its long edge should be at most 1,600 pixels, its area at most 1.56 megapixels, and each numbered badge at least 24 pixels tall. Check 1×, 2×, and a screenshot that needed downscaling.
2. Resize or move the Dock while a session is open. Expect the pill to follow the visible area's bottom-right corner without finishing the session. Then disconnect a marked display and verify that the session finishes and the log names display change. Successfully captured frames should still export. The ¶ menu should report missing frames where applicable. Reconnect and start again.
3. In a disposable debug build, stall a marked frame capture past its deadline while leaving the permission probe and main thread responsive. Finish immediately after the stroke. Expect "No frame to export · 1 timed out" within about five seconds of stroke-down and a usable Start command. Repeat with a successful frame on another pass or display and expect that frame to export. Clear a stalled frame before finishing and verify that it does not hold up Finish.
4. Check export retention. A successful export should create a fresh temporary folder named `pilcrow-<UUID>`, with mode `700` and contiguous filenames `frame-1.png` through `frame-N.png`. Confirm it replaces the preceding export. Finishing with no successful marked frames should preserve the last successful export, if any. Quit and check that Pilcrow removed its latest export folder.
5. To check stale cleanup, with Pilcrow stopped create a disposable `pilcrow-<UUID>` directory with an uppercase UUID in the temporary directory. Also create a `pilcrow-not-an-export` directory, a regular file with a different exact export name, and a symlink with another exact export name pointing to a disposable directory. On launch only the exact-name stale directory should disappear. Clean up the surviving fixtures. If running two instances, verify that starting the second keeps an export still owned by the first.
6. Annotate a non-sensitive, color-managed P3 image on a wide-gamut display. Check the exported PNG's embedded profile and compare unmarked patches in a color-managed viewer. Use `sips -g hasAlpha /path/to/frame-1.png` and expect `hasAlpha: no`. If the log reports a burn-in fallback to sRGB, note the display profile and resulting PNG profile.
7. With Pilcrow stopped, reserve ⇧⌥⌘J in a shortcut utility and relaunch. If Carbon rejects registration, expect "Hotkey registration failed, retrying for up to 3 seconds" in the log. Release the reservation during that window and confirm the toggle works without relaunch. Repeat while holding the reservation past the retry window and expect ¶ ⚠ and Shortcut unavailable. Verify that Start annotating and Finish in the menu still work. Release the reservation, relaunch, and confirm the toggle works.
8. In a disposable test, start a session with access granted, then turn Screen Recording off in System Settings before the first mark. Return and draw, then finish. If macOS lets the process stay open and the frame fails for permission, expect "permission needed" in the frame log and "No frame to export · Screen Recording off" in the ¶ menu. Repeat after capturing a successful frame. Click the editor after revocation so the next stroke starts a fresh pass. Confirm the earlier frame still exports and the menu mentions Screen Recording off. If macOS defers the revocation until relaunch or quits Pilcrow, record that outcome.

## Escape routes

Release ⇧ to interact with the app underneath or the ¶ menu. A drag keeps the mouse until mouse-up or until Pilcrow sees that the left button was released. To finish and export, press Esc or ⇧⌥⌘J, click the pill's Finish, or choose Finish annotating from the ¶ menu. If those controls fail in a disposable test, quit from the ¶ menu, press Ctrl+C in the launching Terminal, or use `pkill -x Pilcrow`. The last two can interrupt an export. Record the stuck state and the route that recovered it.
