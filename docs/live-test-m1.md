# Milestone 1 human live test

Use macOS 26 or later and a disposable document with distinct landmarks near the top and bottom. Use non-sensitive content on every display. Record the macOS version, chip, display arrangement, backing scales, launch method, and actual result for each check.

Stream Pilcrow's log in a separate Terminal window while testing. Frame outcomes, finish reasons and export results are at notice level. Use `--level debug` for per-result voice timing and word counts.

~~~bash
log stream --level debug --predicate 'subsystem == "org.pilcrow.app"'
~~~

## Screen Recording gate

Use a fresh permission history. For a signed bundle, follow the reset steps in [Build and sign Pilcrow](building.md). For a bare SwiftPM executable, macOS may attribute access to the launcher, such as Terminal. Start with a launcher without Screen Recording access and clear Pilcrow's saved request flag with the command below. Use the same launcher and build throughout the check.

~~~bash
defaults delete Pilcrow ScreenRecordingRequested 2>/dev/null
~~~

1. Launch Pilcrow, switch to the editor, and press ⌥D. Expect a normal titled Pilcrow Permissions window to appear in front, with a Screen Recording row showing Off and a Grant… button. The rest of the desktop should accept input normally. Verify that Start annotating in the ¶ menu brings forward the same window. Expect no canvas, pill, or macOS prompt from either start command.
2. Click Grant… and leave access off in the macOS prompt. Check that the row stays Off and its button changes to Open System Settings…. Click it and confirm that it lands in Privacy & Security at the screen recording controls. Record the app or launcher listed there. The ¶ menu should also report Screen Recording as Off. Check that the window offers Quit & Reopen under "Already turned it on?" for a bundled app, or gives manual relaunch instructions for a bare executable.
3. Grant access with the Pilcrow window open. The window samples preflight about once a second. Record which outcome macOS gives you. Available follows a successful capture check. "macOS needs Pilcrow to reopen" follows a failed or timed-out check. If the row stays Off, use "Already turned it on?" and Quit & Reopen, or the manual relaunch instructions. If preflight turns true, expect one "Screen Recording probe started" log entry. Leave the window open for several seconds and open the ¶ menu a few times. Expect no further probes until you explicitly start or preflight becomes false and then true again.
4. For either reopen outcome on a bundle, click Quit & Reopen and confirm that a new instance opens and the old one exits. Wait about three seconds (the hotkey retry window), then press ⌥D once in the new instance: expect the overlay if access is now Available, or the permissions window if it is still Off. Finish with Esc before the next step. For a bare executable, quit and relaunch from the same launcher. Start again. The ¶ menu should report Available after the check succeeds. Record which reopen outcomes occurred. If a disposable debug build can force the replacement launch to fail, verify that the old instance shows the failure and recovers ⌥D.
5. Once access is Available, click Start annotating in the window or start again with the hotkey or ¶ menu. Expect one fresh probe per Start. A failed Start that brings up the permissions window shares its probe with the window. On success, the window should close and the overlay should appear. Expect no permission probes while the overlay is open, including when you open the ¶ menu. If macOS asks you to keep allowing screen recording, record when the prompt appears. Release ⇧ to reach the prompt or finish using one of the escape routes below.

## Drawing and passes

Show last capture in Finder now opens the persisted D-22 outbox item, containing saved `frame-N.png` files, `mark-N.png` crops, `message-for-agent.md` and `manifest.json`. Earlier references below to `message.md` mean this persisted message file. Normal export writes directly into this item; only failure recovery uses a temporary export. Export counts and failure notes remain in notice logs; the final menu status reports the clipboard copy.

1. Put the caret in the test editor, then start with the hotkey. The compact pill should show “esc” and a mic dot only when voice is running, plus any errors or warnings. Click and type in the editor with ⇧ released. The editor should receive input, and the ¶ menu should still be clickable. Hold ⇧ alone and draw one stroke. Expect a red ring under the pointer while ⇧ alone is held. Release ⇧ partway through the drag, keep moving, then lift the mouse button. The stroke should continue to mouse-up. Click and type again to confirm the editor kept keyboard focus. Check that adding ⌘, ⌥, or Control to ⇧ before clicking leaves the canvas click-through. Pilcrow samples ⇧ about 60 times a second. For repeatable checks, wait a moment after pressing or releasing ⇧ before clicking.
2. In a fresh session, draw two strokes on different landmarks without clicking or scrolling through the canvas between them. Expect badges 1 and 2. Press ⌘Z and check that it removes the second mark and leaves the editor's undo history alone. Draw again and expect badge 3. Finish with Esc and reveal the export from the ¶ menu. Expect `frame-1.png` with marks 1 and 3, crops `mark-1.png` and `mark-3.png`, and `message.md` aligned to the landmarks. Check that the export omits the pill and canvas tint. With the session closed, confirm that ⌘Z reaches the editor again.
3. Draw a mark, release ⇧, and type in the editor without clicking or scrolling. Draw again and confirm that both marks stay visible on the same pass. Release ⇧, scroll the document, then hold ⇧ and draw another mark. The new stroke should start a fresh pass and the earlier marks should disappear from the live canvas. Release ⇧, click something that changes the editor visibly, then hold ⇧ and draw a fourth mark. Finish. Expect three frame images (`frame-1.png` to `frame-3.png`) plus one `mark-N.png` crop per live mark and `message.md` in order, each with the screen state and marks for that pass.
4. In a fresh session, draw twice, click beneath the canvas, and draw a third stroke. Undo that stroke with ⌘Z while the editor is still active. Draw a fourth stroke, undo it with ⌘Z, and finish. Only the marks from the first pass should export. The pill should finish on its first click even with another app active.
5. Try each finish control with a marked session. Confirm the panels disappear, successful frames export, and the log identifies the control with "Session finished via Esc", "Session finished via hotkey", "Session finished via pill Finish", or "Session finished via ¶ menu". Repeat Esc immediately after start and during a drag. Verify the corresponding Start logs ("Start requested via hotkey", "Start requested via ¶ menu", and "Start requested via permissions window Start") when you try those paths. The display change finish reason is checked below. If an external shortcut utility can reserve Esc or ⌘Z before a session, confirm a rejected registration is named in the pill and the pill and menu Finish still work.
6. Put the editor in a native full-screen Space. Start via hotkey with the pointer in that Space. Verify overlay visibility, drawing, click-through, and keyboard focus without a jump to the desktop. Repeat in Stage Manager if available.
7. Interrupt a drag with Mission Control or a screen lock and release the mouse button and ⇧ while the canvas is out of focus. On return, click the editor and its menu bar with ⇧ released. Both should work and a new ⇧ drag should draw. The log line "Stroke ended after mouse release without mouse-up" means two consecutive polls saw the button up before the canvas received mouse-up. Draw and release normally several times and check that the ends of the strokes match where you lifted the mouse. If the window received mouse-up normally or the session finished on a display change, record lost mouse-up recovery as untested.

## Shapes (D-25)

Captures now best-effort record local `strokes.json` for calibration, with full-precision samples through 5,000 points per stroke and a 5 MB capture cap. Draw the shapes that failed again: the loose oval around a chat bubble, about 180 × 100 pt, and the wavy box around an input, about 290 × 95 pt. Try smooth and jittery strokes, plus short lead-in/exit hooks. Record the visible result and reveal the export to retain its JSON for replay. The restored conservative rules may still leave these freeform; collect the evidence before changing thresholds. The JSON must stay out of the clipboard and agent/MCP attachment list.


1. In one pass, hold ⇧ and draw a rough closed box around a line of text, a rough box around a button, a nearly closed circle, an oval with a short overlap, and a lopsided closed blob. Check that the raw ink follows the drag. At pen-up, the boxes should snap to rounded rectangles and the circle and oval to ellipses. The blob should keep its ink. Check the badges at the top-left box corner and on the upper-left ellipse curve. A long, visibly tilted oval should keep its ink as an area. Draw a long three-sided outline with a gap of about 20 pt at the open end and check that it stays plain.
2. Draw an underline and a tick inside the box. Underline the line just below the box, starting about 9 pt from the bottom edge. Try a strike-through starting about 8 pt to its left. Draw a box as four strokes and a capital T as two. All of these strokes should stay plain.
3. Draw a small circle inside a larger box. Start a roughly straight drag in the circle and finish on something you want to point at. Expect the shaft to keep its ink, the head to point at the tip, and the new badge to sit beside the head, leaving the target uncovered. Check that the message links to the circle. Start another underline near that tip, away from the source shapes, and check it stays plain. ⇧-click with a small pointer wobble to drop a pin. Drag from the center of its number to another word. Expect both numbers and the target to be readable. Try a pin near the right edge and check its badge flips left. Draw an arrow toward the frame edge and check that its badge stays in frame beside the head. Press ⌘Z to undo the latest mark and confirm that a new mark gets a new number.
4. Finish and compare the frame and mark PNGs with the canvas. Check that each crop contains its area or the arrow's shaft, head and full badge. Check the pin, the other badge positions and legible export badges at least 24 px tall. The message should use `(box)`, `(circle)`, `(area)`, `(arrow from [n] to its tip)` and `(point)` where expected. Plain marks keep their usual unlabelled lines.

## Displays and export

1. With a 1× display to the left of or above a 2× display, start with the pointer on the secondary display. Expect the pill at the bottom right of that display. In one pass, mark asymmetric landmarks on both displays. Expect one `frame-N.png` per marked display (plus one `mark-N.png` crop per mark and `message.md`), ordered by the first stroke on each. Check upright badges, stroke alignment near all edges, and no offset from the displays' arrangement. Inspect each PNG at actual size. Its long edge should be at most 1,600 pixels, its area at most 1.56 megapixels, and each numbered badge at least 24 pixels tall. Check 1×, 2×, and a screenshot that needed downscaling.
2. Resize or move the Dock while a session is open. Expect the pill to follow the visible area's bottom-right corner without finishing the session. Then disconnect a marked display and verify that the session finishes and the log names display change. Successfully captured frames should still export. Review should show missing-crop placeholders where applicable; the message and export log retain the capture failure. Reconnect and start again.
3. In a disposable debug build, stall a marked frame capture past its deadline while leaving the permission probe and main thread responsive. Finish immediately after the stroke. Expect an "Exported message" notice with a timeout note within about five seconds of stroke-down and a usable Start command. The outbox item should have no PNGs; its message should say "screenshot not available". Repeat with a successful frame on another pass or display and expect its frame and crops to export. Undo the stalled frame’s mark before finishing and verify that it does not hold up Finish.
4. Check retention. Finish should export directly into a fresh private outbox item without creating a normal temporary export. Earlier outbox items remain available for 24 hours, including text-only items. Finish an empty session and check that "Nothing to send" appears and the previous item remains available. Quit and confirm saved outbox items and any failure recovery exports remain.
5. To check stale cleanup, with Pilcrow stopped create a disposable `pilcrow-<UUID>` directory with an uppercase UUID in the temporary directory. Also create a `pilcrow-not-an-export` directory, a regular file with a different exact export name, and a symlink with another exact export name pointing to a disposable directory. On launch only the exact-name stale directory should disappear. Clean up the surviving fixtures. If running two instances, verify that starting the second keeps an export still owned by the first.
6. Annotate a non-sensitive, color-managed P3 image on a wide-gamut display. Check the exported PNG's embedded profile and compare unmarked patches in a color-managed viewer. Use `sips -g hasAlpha /path/to/frame-1.png` and expect `hasAlpha: no`. If the log reports a burn-in fallback to sRGB, note the display profile and resulting PNG profile.
7. With Pilcrow stopped, reserve ⌥D in a shortcut utility and relaunch. If Carbon rejects registration, expect "Hotkey registration failed, retrying for up to 3 seconds" in the log. Release the reservation during that window and confirm the toggle works without relaunch. Repeat while holding the reservation past the retry window and expect ¶ ⚠ and Shortcut unavailable. Verify that Start annotating and Finish in the menu still work. Release the reservation, relaunch, and confirm the toggle works.
8. In a disposable test, start a session with access granted, then turn Screen Recording off in System Settings before the first mark. Return and draw, then finish. If macOS lets the process stay open and the frame fails for permission, expect "permission needed" in the frame log and "Screen Recording off" in the ¶ menu. The export should contain only `message.md`. Repeat after capturing a successful frame. Click the editor after revocation so the next stroke starts a fresh pass. Confirm the earlier frame still exports and the menu mentions Screen Recording off. If macOS defers the revocation until relaunch or quits Pilcrow, record that outcome.

## Voice

Run these checks on a signed build with Screen Recording granted. Use a disposable document and non-sensitive narration.

1. Start a session before setting up voice. The pill should show “esc” without a mic dot. Draw and finish a mark. Open **Permissions…** in the ¶ menu. On a fresh permission history with no model installed, click **Turn on** in the **Voice narration** row. Deny the microphone request once and verify that no model download starts and the row offers **Open System Settings…**. Grant access in Settings, return to Pilcrow, then click **Turn on**. With a fresh history where you grant the prompt, the same click should also start the model download. Check inline progress and look for **On** when it finishes. Verify that neither setup nor starting a session shows a Speech Recognition permission prompt.
2. Start a session. Expect a dim dot while voice starts. Speak while drawing a mark on "heading" in "Move the heading down" and another on "footer" in "Align the footer left." Check that the dot responds to input level and the pill shows no live caption. Press Esc as you finish the last word. The overlays should disappear immediately and the mic should stop about a quarter second later. In Review, verify that mark 1 has “Move the heading down” and mark 2 has “Align the footer left,” allowing for recognized punctuation. In `message-for-agent.md`, verify that the inline numbers still follow the words spoken at pen-down and that the last word appears once. A speech-only session should copy words with no images and show the one-row HUD with a text.quote glyph.
3. Start with a built-in or wired microphone. Speak and mark, switch the default input, and keep speaking during the handoff. Check for a new engine and first-buffer anchor in the log. Speech the replacement engine captures while the old analyzer drains should appear in order, with the second mark aligned and no repeated words at the boundary. Try a same-format switch and Bluetooth headphones. Record the time to the first Bluetooth buffer. A first buffer within five seconds should keep voice active. Disconnect the device without a replacement and check that the pill reports the interruption and Finish still works.
4. Revoke microphone access and start with the hotkey. The pill should stay quiet about voice. Draw, undo and Finish. Check that the copied message includes the remaining marks and images, and that Start shows no permission prompts for voice.
5. With the model installed, disconnect the network and confirm narration still works. Check the export folder for audio files and the log for engine state, first-buffer uptimes, input latency and segment anchors. In the `voice` category, check the debug line for each result's audio range, `isFinal`, finalization time and word count. Look for volatile revisions followed by finals over the same audio, including while pressing Esc. If the log reports dropped overlapping final words, check the counts and ranges and confirm that the newer final's remaining words appear in Review. Voice logs should contain no transcript text. Repeat the mark-timing check on wired and Bluetooth inputs and record any consistent offset in milliseconds.
6. Say a greeting, pause, then say "I want this piece" as you draw an area and "to go on this side" as you draw its arrow. Draw two more areas on "And this" and, after a short pause, "this following box." Draw the last arrow on "to go up," keep speaking through "so that we have some good padding from down below," and press Esc near the end. Check that the greeting stays in the paragraph and all five marks have their own words. Repeat with "uh," "um," "I I" and "on on." Disfluencies that the final recognizer result retains should remain visible in the paragraph. The English fix lines should remove fillers and immediate stutters while keeping quoted words and repeats across sentence ends.
7. Say "Move this over here and delete that." Put each mark down just after "this," "here" and "that." Check for "Move this," "over here" and "and delete that" in order. The inline numbers should appear near those breaks even when a following word has just started. Try drawing near the end of a new sentence while the previous drag overlaps its beginning. Next, say "Make these three bigger" and place three quick pins or circles without speaking between them. All three should receive the same instruction.
8. Say "Make this header smaller." Pause about one second and mark the header. Say "And this one blue," pause about one second and mark the second item. Check that both lines match the intended item. Repeat in the other order, drawing each of three marks before explaining it and moving to the next mark just as the previous explanation ends. Check for three separate fix lines in order.
9. Draw one mark, then dictate four short phrases with about 0.7 s of silence between phrases. Check that one fix line includes all four. Wait more than 2.5 s after the last phrase, then say "Okay, that is everything, thanks." Check that the closing words stay in the paragraph.
10. Narrate a mark, undo it, pause and redraw in silence. Check that the replacement inherits the original instruction. Repeat with a new instruction started after undo and before redraw. Check that the original words stay in the paragraph and the replacement gets the new words.
11. Say "Give a quick," pause, then "Uh, cry," to exercise the capitalized filler case if the recognizer inserts an ellipsis. Try "in in the corner," "this, this button" and "that that that." Check the fix lines for "in the corner," "this button" and two copies of "that" if the recognizer emits all three. Compare with the paragraph's raw text. In the analyzer log, look for a volatile hypothesis starting just inside previously finalized audio and an overlap between two finals. Check that the new tail survives and any word spanning the join appears once. If a handoff produces a drain timeout, check that the provisional tail survives once before the next segment.

## Escape routes

Release ⇧ to interact with the app underneath or the ¶ menu. A drag keeps the mouse until mouse-up or until Pilcrow sees that the left button was released. To finish and export, press Esc or ⌥D, click the pill, or choose Finish annotating from the ¶ menu. If those controls fail in a disposable test, quit from the ¶ menu, press Ctrl+C in the launching Terminal, or use `pkill -x Pilcrow`. The last two can interrupt an export. Record the stuck state and the route that recovered it.
